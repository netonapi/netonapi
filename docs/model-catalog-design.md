# 对外模型目录（2026-10-28）

## 问题

用户能看到、能调用哪些模型，过去由两件事被动决定：价格表里有这一行，且某个启用的渠道在 `models` 里列了它。
运营从价源导入了 338 条价格，又在两个渠道上「拉取模型」（会把上游列出的几百个模型并进渠道清单），两边一交，
用户的模型列表就成了几百个上游的杂货——这不是我们要卖的东西。

## 原则

**对外提供哪些模型只由我们精选的模型目录决定。** 上游可能有上百个、各自支持上百个模型，它们只是底层可切换的线路，
不会让任何模型自动对外。我们只卖几个主流模型。

## 规则

1. **模型目录 = 价格表里 `listed = 1` 的行。** 一行同时是「这个模型对外」与「它卖多少钱」。
   - 管理台手动添加的模型默认上架；价源导入 / 校准新建的行默认下架，只当价格参考库（添加模型时带出官方价）。
   - 下架的模型对用户不可见、不可调用：用户模型列表、价格页、`/v1/models` 不列；转发回 `404 model_not_found`
     （与「没有这个模型」同一个回答，不暴露价格库里有什么）。
2. **上游只是线路。** 渠道新增 `supported_models`：「拉取模型」只写它（这个上游**能**服务什么），
   不再并进 `models`（这个上游**正在**为我们服务什么）。
3. **模型 → 服务上游。** 在模型上勾选服务它的上游（候选是支持它的上游，也允许手填），每条可填上游侧的模型名。
   保存时写回各渠道的 `models` 与 `model_mapping`——路由仍按渠道优先级、权重与故障切换走，不另起一套。
4. **对外可见 = 上架 且 至少一个启用的上游在服务它。** 进一步按用户：上架模型还可设开放范围（所有用户 / 指定分组与用户），
   每个用户能用的模型与价格以服务端为他算好的价目表为准，见 [gateway-pricing-spec.md §4.3](gateway-pricing-spec.md)。

## 迁移（V023）

- `gateway_model_prices.listed SMALLINT NOT NULL DEFAULT 1`；已有行全部置 0（导入 / 校准来的价格库，由运营挑出来上架）。
- `gateway_channels.supported_models TEXT NOT NULL DEFAULT ''`；已有渠道的 `models` 挪进 `supported_models`，
  `models` 与 `model_mapping` 清空（拉来的清单不是运营的选择；由模型目录重新指定服务上游）。

## 接口

- `GET /admin/gateway/channel/model-routes?model=` → 每个渠道：是否支持、是否在服务、上游模型名、优先级、状态。
- `PUT /admin/gateway/channel/model-routes` `{model, routes:[{channelId, upstreamModel?}]}` → 改写各渠道的服务清单与映射。
- `PUT /admin/gateway/price/listed?id=&listed=` → 上架 / 下架。
- `POST /admin/gateway/channel/models/{id}` 拉到的列表写进 `supported_models`。

## 管理台

- 「模型与定价」默认只显示已上架的模型，可切到「价格库」挑模型上架；体检的亏本 / 偏薄 / 无渠道计数只算上架的模型。
- 上架的模型行内「服务上游」：列出全部渠道，默认只看声明支持它的上游，勾选并可填上游侧模型名。
- 「上游渠道」的「拉取模型」只刷新「上游支持的模型」，提示去「模型与定价」设置对外模型。
