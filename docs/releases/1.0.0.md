# NetonAPI 1.0.0：从运营平台出发设计的 AI API 中转站

2026-11-06

NetonAPI 是一个自托管的大模型 API 中转网关：一个 Key 调用 OpenAI、Claude、Gemini、DeepSeek、Qwen、GLM、Kimi、Grok 等主流模型，
按 token 计费，自带运营后台与用户控制台。今天发布 1.0.0 正式版。

## 为什么再做一个中转站

现有的开源中转站大多从「把请求转出去」出发，计费是在转发上叠加的倍率。真正运营一个中转站，难的是另外几件事：
**每个模型卖多少钱、拿货多少钱、这一单赚没赚钱、给大客户的折扣会不会卖亏、用户看到的价格和账单对不对得上。**
NetonAPI 从第一行代码起就围绕这些问题设计。

### 1. 以官方价为锚定价

客户比价的锚点是官方价（「Claude 官方 $3，这里 7 折」）。NetonAPI 的售价直接写成「官方价 × 加价率」，
给一组用户或单个大客户的优惠写成「官方价 N 折」——官方价调整时自动跟随，承诺一直成立。
不需要去换算一层层倍率。

### 2. 每条渠道都有真实成本，亏本的价格保存不了

每条上游渠道记录自己的拿货价：官方价折扣、自动拉取上游中转站的价目接口、或按模型手填；成本异常变动先挂起，等运营确认。
任何定价（全站价、分组价、给单个用户的协议价）保存前都按**真实会走的每条渠道**核算毛利，**低于成本直接拒绝**。
定价体检列出每个「分组 × 渠道」组合的最差毛利，利润看板按分组、渠道统计收入、成本与亏损。

### 3. 展示的单价就是扣费的单价

扣费 = tokens × 用户在控制台看到的单价，逐项向上取整；价格页、控制台、账单三处是同一个数，客户可以逐笔对账。
上游用量数据不规范（缓存数比输入还多、缓存价缺失等）时按保守口径计，不少收、不白送。

### 4. 钱的账是两阶段的

每次请求先按上界预留额度，结束后按实际用量结算，定价快照随请求冻结——中途改价不影响在途请求。
进程崩溃后自动恢复，说不清的账进人工复核队列，**不会自动退款也不会重复扣费**。

### 5. 给运营用的后台

- **协议定价**：搜一个用户，逐模型（或批量）设「官方价 N 折」，实时显示他的价格和毛利。
- **计费分组由 API Key 决定**：专线、特价直接指定到某把 Key，开了就生效。
- **菜单与按钮级权限**，预置网关运营、财务、客服、只读四个角色，建账号勾一个角色就能用。
- **API Key 只在创建时显示一次**，库里只存哈希；上游渠道 Key 加密存储，支付密钥只写不读。

## 1.0.0 包含什么

- **接入**：OpenAI（Chat Completions、Responses、Embeddings、Images、Audio、Rerank）、Anthropic Messages、Gemini 原生接口，
  入站与上游协议**任意方向互转**（工具调用、图片、thinking、缓存用量保真），流式与非流式全覆盖；Claude Code、各家官方 SDK 直接可用。
- **上游**：OpenAI 兼容站（含各类中转站）、Azure OpenAI、Anthropic、Gemini、AWS Bedrock、Vertex AI。
- **路由与容错**：优先级 + 权重，失败自动换渠道（上游报「没有这个模型」也会换），Key 自动停用与冷却，定时测速，长回答不截断。
- **计费**：按 token、按次、按长上下文分档；缓存读写分别计价；全站价、分组价、协议价三层，逐笔对账。
- **钱**：管理员手动充值、兑换码、在线支付（支付宝、四方支付，可扩展），完整余额流水。
- **运营**：概览（收入 / 成本 / 毛利、每日趋势、模型与用户排行、渠道健康）、价源同步与校准、调价记录、用量日志、结算复核、
  Prometheus 指标。
- **用户**：注册登录（账号密码、手机验证码）、API Key 自助管理（预算、有效期、模型范围、IP 白名单）、用量与账单、模型价格表、接入说明。
- **部署**：Kotlin/Native 编译的**单个原生可执行文件**，运行期无 JVM；依赖 PostgreSQL（Redis 可选）。

## 与主流开源中转站对照

| | NetonAPI 1.0 | new-api | one-api |
|---|---|---|---|
| 定价方式 | 官方价为锚，「官方价 N 折」 | 模型 × 补全 × 分组倍率 | 分组 × 模型 × 补全倍率 |
| 按用户 × 模型的协议价 | 有 | 按用户分组倍率 | 按用户分组倍率 |
| 渠道真实成本 / 毛利保护 | 有，低于成本保存不了 | 公开文档未涉及 | 公开文档未涉及 |
| 展示单价 = 扣费单价 | 是，逐笔可对账 | 预扣后多退少补 | 预扣后结算 |
| 账务 | 两阶段预留 → 结算，崩溃可恢复 | 预扣 + 后结算 | 预扣 + 后结算 |
| API Key | 只显示一次，只存哈希 | 可随时查看 | 可随时查看 |
| 协议互转 | OpenAI / Anthropic / Gemini 任意方向 | 四种文本协议互转 | 统一为 OpenAI |
| 上游类型 | 6 类（含所有 OpenAI 兼容站） | 数十种 | 30 余家 |
| 任务类接口（MJ、视频） | 暂不支持 | 支持 | 不支持 |
| 部署 | 单个原生可执行文件，PostgreSQL | Go / Docker，多种数据库 | Go / Docker，SQLite / MySQL |

完整对照见 [README](../../README.zh-Hans.md#能力对照)。new-api、one-api 两列依据其公开文档整理（2026-11）。

## 已知限制

刻意写出来：

- 不支持 Midjourney、Suno、视频生成等任务类接口；上游类型少于 new-api（但所有 OpenAI 兼容站都能接）。
- 用户侧暂无第三方登录（GitHub、OIDC 等）与两步验证。
- 只支持 PostgreSQL。
- Docker / compose 部署路径尚未在真实 Docker 宿主上跑过；推荐按 DEPLOY.md 的裸机方式部署。
